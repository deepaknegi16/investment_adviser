01 — the organising principle

Nothing fast waits on anything slow

free & deterministic metered AI (free tier, quota'd) third-party

The rule that produced this shape is arithmetic in code, judgment in the model. Returns, moving averages, RSI, screening scores, factor decomposition and position sizing are all deterministic, so they are Python — free, instant, and identical every run. The model is spent only where a person would genuinely have to weigh something: what a news item means, which twenty names out of a hundred deserve a look, how to phrase an outlook.

The corollary matters more than the rule: because the deterministic layer never calls a model, the whole dashboard still works with no API key at all. AI panels degrade to a stated reason; nothing else notices.

02 — architecture

One process, one file, no services

There is no message queue, no Redis, no vector database and no container. For one user with a watchlist of thirteen names, each of those would be infrastructure to operate rather than a problem solved — the RAG corpus is small enough that a NumPy cosine scan over SQLite rows is instant, and the caches that matter are in-process dictionaries with TTLs.

03 — the agents

Three agents, one runner

Gemini will not accept search grounding, custom function tools and strict JSON output in a single request, so an agent run is an explicit pipeline rather than one call. All three agents compose the same three primitives in runner.py, which also owns the retry ladder and the Groq fallback.

on click · cached per day

Analyst

Tool loop over market data, then a search-grounded news pass, then schema-constrained synthesis. Produces a sourced news digest, a short and long-term outlook, and a call. Pinned to Gemini: its citations are the model's output, so a Groq fallback would silently drop them.

daily · hybrid

Screener

A free deterministic momentum pre-screen cuts ~110 Nifty names to 30; the model only ranks those 30. AI judgment where it adds value, arithmetic in code everywhere else — the pattern the whole app is built on, made explicit.

cron · unattended

Gold Watch

The only agent that runs with nobody watching, so it is the only one with guardrails and an eval suite. Discovery is RSS rather than AI, which is what lets it keep working after the daily search quota is gone.

Why the third agent exists at all. A gold ETF has no earnings, no management and no order book, so the Analyst's entire strategy — call the technicals, search for company news, judge valuation — has nothing to bite on. GOLDBEES needed a different question asked.

04 — the gold chain

Which link moved?

GOLDBEES₹125.84 = k0.00929 × gold $/oz4,440 × USDINR94.82 ÷ g / troy oz31.1035

A rupee-denominated gold ETF is three independent drivers multiplied together, and only one of them is gold. k is the grams backing one unit times the Indian domestic premium — import duty, local scarcity, fund expense. Tracking it separately is what lets the agent tell three things apart that look identical on a price chart.

If this moved……the leg isWhat to watch
Gold rallied in dollarsgold_usdFed, real yields, central banks, geopolitics
The rupee weakenedUSDINRRBI, oil, current account, FII flows
Delhi changed the import dutykBudget, customs notifications, CBIC

The decomposition is testable, and it tested true. k steps +8.3% across April–June 2026, matching India's import-duty rise from 6% to 15% in May. Over 2026 to date the ETF gained ~13% while dollar gold was flat — the entire move was the rupee and the duty. An agent watching only "gold news" would have explained none of the year's actual return.

05 — position sizing

How much, not just whether

Factor weights come from the published cross-sectional literature rather than from what was convenient to compute — momentum, quality and value at 25% each, trend 15%, and analyst consensus cut to 10% because the evidence supports revisions rather than rating levels. One-month momentum is excluded outright: at that horizon the effect reverses.

06 — the engineering record

What measurement changed

Several parts of this design exist because something was measured and found wanting. These are the load-bearing corrections, kept here because the reasoning matters more than the result.

The first sizing model implied 17.4% portfolio turnover per day

Conviction came from step functions — +1 if price > SMA50 — so a stock sitting on its average flipped a whole point on noise. At Indian brokerage plus STT, with sub-12-month gains taxed at slab rate, that column was worse than none. Continuous cross-sectional ranks brought it to 2.2%.

The watcher's first live run found zero events and reported calm

News discovery used Gemini's search grounding, whose free daily quota was already spent. Nothing errored; the output simply looked fine. Discovery moved to RSS — free and unmetered — and the model was demoted from finding the news to scoring it.

Yahoo publishes ROE for 7% of Indian small caps

The quality gate was rejecting on missing data rather than weak fundamentals. EPS and book value are present for ~100%, and ROE is their ratio, so it is now derived where absent and flagged as such. Coverage went 3/40 → 40/40.

Parallel batch downloads silently lost 113 of 140 symbols

yf.download already threads internally, so four concurrent chunks stacked concurrency on concurrency and Yahoo answered with empties that looked exactly like ordinary rejections. Serial chunks: 140/140.

Two tables each summing to 100% implied 190% of a portfolio

Holdings and screener picks were sized as independent baskets, so one stock in both lists showed 15% in one and 5% in the other. There is one pot of money, so there is now one allocation over the union.

A missing .env silently downgraded auth from locked to open

AUTH_PASSWORD fell back to a default that .env.example shipped verbatim — and the app kept serving traffic. The startup hook now refuses to boot without a password, and rejects the published example value by name.

The pattern across every row: degrade loudly, never silently. The one exception the design fights hardest is a component that fails in a way indistinguishable from working — which is why an unattended watcher that finds nothing has to prove it could still see.

Four of the twelve tables exist purely to answer "is this working?" — chat quality, RAG eval scores, gold eval verdicts and guardrail violations all surface through a single metrics endpoint. For a system whose outputs are judgments rather than facts, that ratio is deliberate.

Backend: FastAPI · SQLAlchemy · SQLite · yfinance · google-genai, on a free Gemini tier with a Groq fallback. Frontend: React + Vite, no UI framework. Auth: HS256 JWT, single user.
